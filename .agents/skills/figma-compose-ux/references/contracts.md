# Version 1 evidence contracts and commands

All JSON documents are objects with `schema_version: 1`. No JSON NaN/Infinity. Bounds are `[left, top, right, bottom]`; IDs/tags must be unambiguous. Preserve unknown raw evidence alongside this normalized representation. CLI functions are independently usable via `scripts/uxlib`; they return serializable objects and raise errors for invalid inputs.

## Design and intent

```json
{
  "schema_version": 1,
  "design": {"origin": "figma_export", "file_key": "file", "node_id": "10:1", "revision": "export-snapshot-1", "reference_image": "reference.png", "reference_scale": 1, "evidence": ["figma-context.json"]},
  "viewport": {"width_dp": 360, "height_dp": 592, "figma_units_per_dp": 1},
  "scope": ["visual", "structure", "behavior"],
  "environment": {"density": 3, "font_scale": 1, "locale": "en-US", "theme": "light", "rotation": 0},
  "nodes": [{"id": "10:2", "name": "Save", "bounds_dp": [24,124,120,164]}],
  "requirements": [
    {"id": "save.bounds", "kind": "bounds", "node_id": "10:2", "state": "empty", "tolerance_dp": 1},
    {"id": "save.disabled", "kind": "property", "node_id": "10:2", "state": "empty", "property": "enabled", "expected": false},
    {"id": "save.parent", "kind": "parent", "node_id": "10:2", "state": "empty", "parent_tag": "ci.form", "hierarchy_kind": "unmerged_semantics"},
    {"id": "save.mapping", "kind": "code_connect", "node_id": "10:2", "state": "empty"},
    {"id": "save.visual", "kind": "pixels", "node_id": "10:2", "state": "empty"},
    {"id": "save.flow", "kind": "transition", "node_id": "10:2", "from_state": "valid", "action": "click", "action_tag": "ci.save", "to_state": "success", "postcondition": {"tag": "ci.confirmation", "property": "text", "expected": "Saved"}}
  ]
}
```

`origin`: `fixture`, `figma_mcp`, or `figma_export`. Each requirement references a known node, including frame-wide pixel checks (use its frame node if appropriate). All design geometry is already normalized into content-relative dp; original Figma geometry stays in receipts. `reference_scale` is PNG export scale, `figma_units_per_dp` gives the units conversion. If content size differs from the selected reference variant, alignment errors rather than stretching.

Supported requirement kinds are shown above. Unknown kinds remain inconclusive. Explicit `applicable: false` needs a nonempty `reason` to become `not_applicable`. Missing properties are unknown, not false. `environment` fields, when supplied, must match capture metadata; different font-scale/locale variants should have their own intent contract. An environment mismatch is incomparable rather than automatically a layout defect.

Code Connect input:

```json
{"schema_version":1,"mappings":[{"node_id":"10:2","framework":"compose","component":"AppButton","source":"app/AppButton.kt"}]}
```

`compose`/`jetpack-compose` are accepted framework labels. Project-relative `.kt` paths only. `prepare --source-root` verifies source containment/existence and hashes it, producing `code_connect.mappings[].supported/source_exists/source_sha256` and an `issues` array. Absent or incompatible mapping is an unresolved issue; malformed design geometry is an input error. `prepare` also hashes `design.reference_image` into `design.reference_sha256` (path relative to input contract or absolute). The Python `prepare_design` library only validates source metadata; callers that bypass CLI must record that image hash themselves. Keep artifact paths valid when moving manifests.

## Runtime capture and tag map

```json
{
  "schema_version":1,"build_id":"instrumented-abc","build_binding":"declared","capture_id":"empty-1","state":"empty","hierarchy_kind":"accessibility","origin":"device",
  "device":{"density":3,"font_scale":1,"locale":"en-US","theme":"light","rotation":0,"api":35,"fingerprint":"actual-build-fingerprint"},
  "viewport_px":[1080,1920],"insets_px":{"left":0,"top":72,"right":0,"bottom":72},
  "image":"screen.png","image_sha256":"SHA256_OF_ORIGINAL_PNG","evidence":["ui.xml","window.txt"],
  "nodes":[{"id":"n0","parent_id":null,"tag":"ci.save","bounds_px":[72,444,360,564],"text":"Save","enabled":false,"clickable":true}]
}
```

`normalize` adds `content_size_dp` and each node's `bounds_dp`: `[(left-insetLeft)/density, (top-insetTop)/density, ...]`. No clipping to make bounds match. Supported hierarchy labels: `accessibility`, `unmerged_semantics`, `composition`. Parent checks accept only explicitly comparable accessibility or unmerged Semantics. The composition label requires a real adapter and is never generated by UI Automator.

Both `normalize` and the adb collector require all seven `device` fields (including for fixtures). If only density is known, report the arithmetic separately and keep canonical collection incomplete; never invent live metadata. The collector it does not guess them. It reads display 0 screenshot/UIA/WMS, records raw files/hash, and creates a UUID child directory in `--output-dir`. Optional metadata `apk_path` binds local base APK bytes to the installed package using `pm path` and device `sha256sum`, writes a receipt and sets `build_binding: verified`. An `apk_sha256` string alone does not verify the installation. `build_id` remains a declared label: keep the source/build receipt that binds the label and hash to your instrumented tag map. A custom adapter must provide equivalent evidence before using `verified`.

```json
{"schema_version":1,"build_id":"instrumented-abc","bindings":[{"node_id":"10:2","tag":"ci.save","composable":"AppButton","source":"app/AppButton.kt"}]}
```

The tag map is for this exact build. Duplicate nodes/tags and stale builds cannot establish identity. The script's Code Connect check establishes mapping consistency, not actual runtime execution of a source function.

## Actions and pixel evidence

```json
{"schema_version":1,"build_id":"instrumented-abc","steps":[{"from_capture":"valid-1","to_capture":"success-1","action":"click","tag":"ci.save","status":"passed","evidence":["trace.log"]}]}
```

Transition verdicts require actual matching before/after captures, an observed enabled click target, trace evidence and the specified postcondition. A claimed `status: passed` without observations is inconclusive. This schema observes evidence from a project-specific runner; it does not itself execute gestures.

`align` writes a new image and registration JSON with crop box, uniform scale, original/aligned hashes, capture ID and design revision. `compare --registration` checks the actual image hash/path before attaching provenance to `pixels.json`. `assess` requires matching design reference hash, raw capture hash, revision, state and capture/build identity for a pixel verdict. The reference/actual/diff copies and their artifact hashes are kept. `assess` reopens those artifacts and recomputes changed pixels; an isolated `passed: true`, missing measurements, changed files or inconsistent thresholds stays inconclusive. Transparency requires explicit RGB `--background R G B`. Tolerances default to zero; specify reviewed thresholds explicitly. Thresholds are metrics, not an overall UX score.

## Independent CLI steps

From the skill directory (`UX` is a convenience shell variable):

```bash
UX="$PWD/scripts/ux.py"
python3 "$UX" prepare --design run/design.json --code-connect run/code-connect.json --source-root /path/to/project --output run/prepared.json
python3 "$UX" instrument --project-root /path/to/project --plan run/patches.json --session /tmp/ux-session-unique
# Build/install/drive the required state with the project runner, then:
python3 "$UX" collect --serial emulator-5554 --package com.example.app --build-id instrumented-abc --state empty --metadata run/metadata.json --output-dir run/captures
# Or normalize a project adapter's capture:
python3 "$UX" normalize --input run/adapter-capture.json --output run/empty.json
python3 "$UX" align --design run/prepared.json --runtime run/empty.json --output run/aligned.png --registration run/registration.json
python3 "$UX" compare --reference run/reference.png --actual run/aligned.png --registration run/registration.json --output-dir run/comparison
python3 "$UX" assess --design run/prepared.json --runtime run/empty.json --runtime run/valid.json --runtime run/success.json --tag-map run/tags.json --trace run/trace.json --visual run/comparison/pixels.json --output run/assessment.json
python3 "$UX" report --assessment run/assessment.json --output run/report.md
python3 "$UX" cleanup --session /tmp/ux-session-unique
```

`collect` prints the actual capture directory/runtime JSON path; use that file in subsequent steps. Do not assume the root `run/captures` contains the final JSON directly. Collection never installs/launches/resets the device. It uses argv and bounded 15-second adb commands. The strict WMS parser requires explicit visible/hidden status and navigation sources from the chosen initial InsetsState. Unknown/vendor layouts fail with retained diagnostics; supply an adapter rather than inventing sizes.

Cleanup belongs in `finally` in an agent/script orchestrator, not merely as the last command in a success-only shell chain. Conflicts are preserved and reported. Exit codes: `0` successful operation/passing declared checks, `1` failed check, `2` invalid input/collection error, `3` inconclusive assessment or cleanup conflicts. Handle `3` explicitly in CI; never accidentally approve missing evidence via `|| true`. The `demo` command returns 0 when the tooling self-test meets expected results; its generated UX assessment deliberately remains fixture-only/inconclusive.

## Canonical result

`assessment.json` contains `schema_version`, `overall_status`, `verdict_scope: declared_requirements`, `validation_scope: fixture_only|provided_evidence`, `summary` counts, `coverage {evaluated,total,ratio}`, `provenance`, `findings`, `design_issues`, `limitations`. Preparation issues remain visible in JSON/Markdown even when another missing prerequisite blocks a finding. Each finding includes requirement `id/kind/node_id`, status, expected, observed, reason, evidence, and available runtime tag/source/capture attribution. `binding_status` explicitly labels `stale_build`, `matched_build` or `unresolved`; a source path in a stale binding is a declaration, not verified attribution. Provenance includes the complete supplied tag map. Statuses are `pass`, `fail`, `inconclusive`, `not_applicable`.

Any observed failure gives overall `fail`; otherwise missing evidence/scope, synthetic fixtures, unverified APK binding or no requirements prevents overall pass. A pass only covers the declared requirements. `coverage.ratio` is evaluation coverage, not visual similarity or UX quality. Markdown is a projection of the same result; do not invent an additional score.
